# Worker 池 · 负载均衡任务调度

纯原生 Web 技术（Web Worker + DOM + Canvas + IndexedDB），无任何框架。

## 运行

```bash
cd B
python3 -m http.server 8000
# 打开 http://localhost:8000
```

> 注意：直接以 `file://` 打开时浏览器会禁止创建 Worker，
> 此时系统会自动降级为主线程执行（界面中 Worker 标记为"降级"），
> 这本身就是"Worker 创建失败降级"能力的演示。完整体验请用 http 服务。

## 功能

- **Worker 池**：默认 4 个 Worker，可输入数量动态增减（减少时忙碌的 Worker 干完当前任务后退出）。
- **负载均衡**：中央优先级队列，任务总是派给"累计忙碌时间最短"的空闲 Worker。
- **任务属性**：优先级（高/普通/低）、超时（ms）、重试次数、取消。
- **负载可视化**：Canvas 绘制每个 Worker 的实时利用率条 + 全局平均利用率曲线。
- **任务历史**：任务进入终态即写入 IndexedDB，刷新页面后仍可查询，可一键清空。

## 异常与边界处理

| 场景 | 行为 |
| --- | --- |
| Worker 创建失败 | 自动降级为主线程分块执行（`InlineWorker`），界面标记"降级"；也可用复选框主动模拟 |
| 任务超时 | 终止并重建该 Worker（硬中断），任务按重试策略重新入队或失败 |
| Worker 崩溃 | `error` 事件触发后回收并重建 Worker，在途任务自动重试；连续崩溃且从未成功则永久降级 |
| 负载不均 | 按累计忙碌时间挑选最闲 Worker；利用率条/曲线实时可见 |
| 任务乱序 | 结果按任务 ID 存入 Map，迟到/乱序消息直接忽略，不丢结果 |
| 取消任务 | 排队中直接移除；运行中先协作式取消，500ms 未响应则强制终止 Worker |
| 页面卸载 | `pagehide`/`beforeunload` 时终止全部 Worker、清理计时器，未完成任务以"已取消"落库 |

## 文件结构

- `index.html` — 页面结构
- `js/pool.js` — Worker 池调度核心（优先级队列、负载均衡、超时/重试/取消、崩溃恢复、降级）
- `js/worker.js` — 真实 Web Worker（分块计算、协作式取消、模拟崩溃/失败）
- `js/inline-worker.js` — 降级执行器（主线程分块执行，接口与 Worker 对齐）
- `js/viz.js` — Canvas 负载可视化
- `js/history.js` — IndexedDB 任务历史
- `js/main.js` — UI wiring 与渲染

## 快速验证

1. "突发提交 ×12"：观察优先级插队、崩溃任务自动重试、负载条均衡分布。
2. 选"超大"工作量 + 超时 3000ms：观察超时中断与重试。
3. 勾选"中途崩溃"提交：Worker 崩溃后自动重建，任务重试成功。
4. 运行中点"取消"：任务立即变为已取消。
5. 勾选"模拟 Worker 创建失败"：全部 Worker 降级为主线程执行，功能不受影响。
6. 刷新页面：历史记录仍在（IndexedDB）。
