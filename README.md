# Worker 池 · 负载均衡任务调度 Demo

纯原生 Web Worker + DOM + Canvas + IndexedDB，无任何框架。

## 运行

Web Worker 不能从 `file://` 加载，需启动本地静态服务器：

```bash
cd 本目录
python3 -m http.server 8080
# 打开 http://localhost:8080
```

## 功能

- **Worker 池**：启动时按 CPU 核数创建 Worker，可动态增减（移除时在途任务自动迁移，不丢任务）。
- **任务调度**：全局优先级队列（优先级高者优先、同级 FIFO），分发给近期利用率最低的空闲 Worker，负载不均自动纠偏。
- **超时中断**：到期 `terminate()` 强杀并重建 Worker，任务按重试策略重投，耗尽后标记失败。
- **崩溃恢复**：`onerror` 捕获崩溃，自动重建 Worker 并重投在途任务。
- **创建失败降级**：`new Worker()` 失败时降级为主线程分块执行器，任务照常完成。
- **取消**：排队任务直接移除；运行中任务先协作取消，500ms 未响应则强杀重建，保证取消生效。
- **乱序安全**：结果统一按 `taskId` 归集，与完成顺序无关。
- **负载可视化**：Canvas 绘制各 Worker 实时负载柱状图 + 占用时间线。
- **任务历史**：IndexedDB 持久化，刷新页面后仍可查询。
- **页面卸载清理**：`pagehide`/`beforeunload` 时终止所有 Worker、清理定时器。

## 文件结构

- `index.html` — 页面结构
- `css/style.css` — 样式
- `js/worker.js` — Worker 执行体（分块计算、进度上报、协作取消、崩溃模拟）
- `js/pool.js` — Worker 池核心（调度、均衡、超时、重试、恢复、降级）
- `js/db.js` — IndexedDB 任务历史
- `js/app.js` — UI 渲染、Canvas 可视化、事件接线

## 演示建议

- **负载均衡**：点「突发 12 个混合优先级」，观察时间线各 Worker 占用趋于均匀。
- **优先级**：先提交一批普通任务占满 Worker，再提交「紧急」任务，日志可见插队执行。
- **超时**：点「提交超时任务」（400 工作量 + 1.5s 超时），观察中断与重试。
- **崩溃恢复**：点「提交崩溃任务」，Worker 崩溃后自动重建，任务重试成功。
- **取消**：提交长任务后点任务行的「取消」。
